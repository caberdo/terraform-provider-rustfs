# AGENTS.md

## Project: terraform-provider-rustfs

A Terraform provider for [RustFS](https://github.com/rustfs/rustfs), an S3-compatible object
storage system, built with the Plugin Framework (v1.19.0) and Go 1.27.3. The provider serves
both the S3 API (through the AWS SDK for Go v2) and the RustFS admin API (`/rustfs/admin/v3`).

Registry address: `registry.terraform.io/caberdo/rustfs`.

## Resources and Data Sources

## Architecture

```
main.go                       # providerserver entry point, version set via goreleaser ldflags
provider/                     # flat package `provider`
├── provider.go               # provider schema, Configure, Resources(), DataSources()
├── registry.go               # registerResource/registerDataSource, sorted by type name
├── all_client.go             # AllClient{S3 *s3.Client, RustClient rustfs.RustfsAdmin}
├── helper.go                 # envOrDefault, secret_key/access_secret resolution
├── rustfs_<name>_resource.go # resource
├── rustfs_<name>_datasource.go # data source (legacy spelling: _data_source.go)
└── *_test.go                 # schema/metadata unit tests + TestAcc* acceptance tests
pkg/rustfs/                   # RustFS admin API client (package `rustfs`)
├── admin_client.go           # RustfsAdmin, RequestData, SigV4 signing, doRequest/DoDirectRequest
└── <name>.go                 # one file per API area (bucket.go, kms.go, user_account.go, …)
docs/                         # generated by tfplugindocs — never hand-edit
examples/                     # provider/, resources/<tf name>/resource.tf, data-sources/<tf name>/data-source.tf
acc_test/docker-compose.yml   # RustFS + golang test-runner services used by CI acceptance tests
tools/                        # build-tagged tools shim keeping terraform-plugin-docs in go.mod
```

### Layout (settled)

The flat layout above is authoritative. The `internal/` move proposed in
[caberdo/terraform-provider-rustfs#2](https://github.com/caberdo/terraform-provider-rustfs/issues/2)
was dropped: no commit from that attempt is an ancestor of `main`, and there is no migration in
progress. A future layout move needs its own accepted issue naming the migration branch, and
Terraform type names stay unchanged because they are part of the provider's public contract.

### Two clients

`Configure` builds an `*AllClient` and hands it to both `resp.ResourceData` and
`resp.DataSourceData`:

- `client.S3` (`*s3.Client`) — S3 API calls (buckets, policies, tags, CORS, versioning, …), built from
  an `aws.Config` with a static credentials provider, `BaseEndpoint` and `UsePathStyle`.
- `client.RustClient` (`rustfs.RustfsAdmin`) — RustFS admin API (`/rustfs/admin/v3`), SigV4-signed
  with the AWS SDK v2 signer (`aws/signer/v4`, service `s3`, region `us-east-01`);
  `DoDirectRequest` targets paths outside the admin base
  (for example `/rustfs/admin/v3` is stripped, used for metrics/health endpoints).

Provider attributes: `endpoint`, `access_key`, `secret_key` (sensitive), `access_secret`
(deprecated alias of `secret_key`), `ssl`, `insecure`. Each is overridden by
`RUSTFS_ENDPOINT`, `RUSTFS_USER`, `RUSTFS_SECRET` respectively; environment variables win when
both are set. A missing endpoint fails `Configure` with an explicit diagnostic.

## Conventions

### Quick Reference

**Configure (mandatory):**

```go
client, ok := req.ProviderData.(*AllClient)
if !ok {
    resp.Diagnostics.AddError(
        "Unexpected Resource Configure Type",
        fmt.Sprintf("Expected *AllClient, got: %T. Please report this issue to the provider developers.", req.ProviderData),
    )
    return
}
r.client = client
```

**Plan/state handling (mandatory):** append diagnostics, then bail out on error.

```go
var plan bucketCorsModel
resp.Diagnostics.Append(req.Plan.Get(ctx, &plan)...)
if resp.Diagnostics.HasError() {
    return
}
```

**Error reporting (mandatory):** a human title plus a contextual detail string.

```go
resp.Diagnostics.AddError(
    "Error creating bucket CORS configuration",
    "Could not create CORS configuration: "+err.Error(),
)
```

**Logging:** `tflog.Trace`/`tflog.Debug` at CRUD boundaries, e.g.
`tflog.Trace(ctx, "created a bucket CORS configuration resource")`.

**Idempotent read/delete:** a resource that is already gone must not fail. Read removes the
resource from state and Delete returns without error:

```go
if err != nil {
    if strings.Contains(err.Error(), "NoSuchCORSConfiguration") ||
        strings.Contains(err.Error(), "NoSuchBucket") ||
        strings.Contains(err.Error(), "404") {
        resp.State.RemoveResource(ctx)
        return
    }
    resp.Diagnostics.AddError(...)
    return
}
```

**Never:** hand-edit `docs/` (generated), rename a Terraform type or attribute (breaks state),
or drop a schema change silently — an attribute that cannot be updated in place must carry
`RequiresReplace()`.

### Patterns

- **Client errors** are plain `errors.New(string(body))` produced by `doRequest`/`DoDirectRequest`
  when the HTTP status is not 2xx (`>299` and `!=200 && !=204` respectively). There is no typed
  error yet, so "not found" is detected by matching the server payload
  (`NoSuchBucket`, `NoSuchCORSConfiguration`, …) or the literal `404` in `err.Error()`.
- **IDs**: simple resources use `ImportStatePassthroughID` on the bucket/name attribute and mirror
  it into `id`; composite resources parse a separator-delimited import ID and report an explicit
  diagnostic when it is malformed.
- **Computed attributes** must be set on every code path or carry `UseStateForUnknown()`;
  otherwise apply fails with "Provider produced inconsistent result after apply".
- **Sets vs slices**: schema sets are converted with local helpers
  (`stringSetFromSlice` / `stringSliceFromSet`) before being sent to the API.
- **Enum attributes** use `stringvalidator.OneOf(...)` with every value the RustFS API accepts.
- **Sensitive attributes** (secret keys, tokens) must be marked `Sensitive: true`.
- **Every attribute carries a `Description`**; tfplugindocs copies it into `docs/`.
- **Examples** are the documentation source: `examples/resources/<tf name>/resource.tf`,
  `examples/data-sources/<tf name>/data-source.tf`, `examples/provider/provider.tf`.

- [ ] API methods in `pkg/rustfs/<name>.go` (admin) and/or via `client.S3` (S3)

### Working on several issues at once

Parallel feature branches must not touch the same shared files. Type registration is
self-service: `provider/registry.go` exposes `registerResource` / `registerDataSource`, and each
resource and data source calls one of them from `init()` in its own file. `provider.go` merely
returns the registry, so it is never part of a feature diff. Server capabilities work the same way:
`registerFeature(FeatureX, featureSpec{...})` from `init()` in the `pkg/rustfs` file that owns the
feature, never a `featureSpecs` entry in `server_version.go`.

Rules for a feature PR:

- **One new type, one new file.** Add the resource/data source (or `pkg/rustfs` API file) with its
  `init()` registration. Do not edit `provider/provider.go` or `pkg/rustfs/server_version.go`.
- **Registry test stays in sync.** `provider/registry_test.go` holds the only golden list of type
  names; add the new name there in the same PR. A dropped registration fails CI.
- **No shared Markdown edits.** A feature PR does not edit `CHANGELOG.md`, `AGENTS.md`,
  `README.md`, `docs/index.md` or `templates/`; add a `changelog.d/<issue>-<kind>-<slug>.md`
  fragment instead. `make generate-tables` refreshes the tables and counts in the release PR.
- **Coverage ships with the feature.** Add unit tests for every new branch in `pkg/rustfs`
  (success and error paths) in the same PR, then run `make coverage` before pushing. Acceptance
  coverage does not substitute: the gate merges both profiles, but a skipped acceptance test
  leaves the new client code uncovered and can fail the `pkg/rustfs` floor. A defensive
  `json.Marshal` guard that no test can reach is a sign the branch belongs in a shared helper,
  not in every method.
- **Coverage floor belongs to coverage issues.** Do not edit `.github/coverage-baseline.txt` or the
  README coverage badge in a feature PR. Raising the floor is a separate change with its own
  measurement.
- **Lifecycle tests live beside the resource.** Add `Test<Name>ResourceLifecyclePaths` to the
  resource's own `_test.go`; do not extend `lifecycle_test_harness_test.go` for one type.
- **Rebase, then regenerate.** Rebase onto `main` and run `make generate` before pushing. Never
  hand-edit `docs/` or resolve its conflicts manually — regenerate instead.

A changelog fragment is named `<issue>-<kind>-<slug>.md`, where `<kind>` is one of `breaking`,
`feature`, `improvement`, `bugfix`, `security` or `chore`, and contains the release-note entry
without the leading bullet. See `changelog.d/README.md` for the convention and examples.

### Branch retention

Feature branches are short-lived: open the pull request, then delete the branch when the
squash-merge lands. A branch that must outlive its pull request is an explicitly documented WIP in
its issue and is never treated as ordinary work. Repository cleanup records the audit
(branch → verdict) instead of deleting branches silently; a squash-merged branch is identified by
its pull request, not by `git branch --no-merged`, because squash-merges keep commits that are not
ancestors of `main`.

### Commands

- **Build**: `go build ./...`
- **Vet**: `go vet ./...`
- **Lint**: `golangci-lint run` (config `.golangci.yml`)
- **Unit tests (client)**: `go test ./pkg/rustfs/... -v` — most files mock the admin API with
  `httptest`; the live CRUD tests dial `RUSTFS_ENDPOINT` and skip themselves when it is unset
- **Unit tests (provider, no server)**: `go test ./provider/... -v -skip '^TestAcc'`
- **Coverage (unit + acceptance)**: `make coverage` writes `coverage.out`; the acceptance container
  (`acc_test/docker-compose.yml`) writes `coverage-acceptance.out` into the worktree, and
  `make coverage-merge` (→ `scripts/merge-coverage.sh`) merges both into `coverage-union.out` and
  prints the combined table. The acceptance job in `test.yml` publishes that table in its summary.
- **Coverage floor (do not lower)**: `make coverage-gate` (→ `scripts/coverage-gate.sh`) fails when
  `coverage-union.out` is below `.github/coverage-baseline.txt`. The `Coverage` check runs it on
  every pull request and the `latest` acceptance cell repeats it on `main`. Raising the floor is part
  of a coverage PR: update `measured_*`/`floor_*` in that file and run `make coverage-readme`, which
  regenerates the README badge and bar chart (CI fails on drift).
- **Fuzz (parsers)**: `make fuzz` runs every fuzz target for `FUZZTIME` (default 30s); the weekly
  `Fuzz` workflow runs the same four commands for 60s each. `go test ./...` replays the committed
  seed corpus (`testdata/fuzz/<Target>/`) without fuzzing, so no target has to be fuzzed to keep
  the suite green. Deeper campaigns: `make fuzz FUZZTIME=10m`
- **Acceptance tests (Docker, as CI runs them)**:
  `docker compose -f acc_test/docker-compose.yml up -d` then
  `docker compose -f acc_test/docker-compose.yml --profile test run --rm test`
  (filter with `-e TEST_FILTER=TestAccBucketResource`)
- **Acceptance tests (local, Podman)**:
  `podman-compose -f acc_test/docker-compose.yml up -d` and

  (the first is the endpoint the server probes, the second the published port the test process dials);

- **Tables and counts**: `make generate-tables` (rewrites only the `AUTOGEN` regions in `AGENTS.md`

- **Changelog**: `make changelog-release VERSION=x.y.z` (groups `changelog.d/` fragments, inserts a

### Testing

**Client unit tests** (`pkg/rustfs`) mock the admin API with `httptest.NewServer` and a
`RustfsAdminConfig` pointed at the test server; no RustFS instance is required. Payloads should be
copied from the RustFS admin API responses, not invented from the Go structs.

**Provider tests** split into schema/metadata unit tests (`Test<Name>Schema`,
`Test<Name>Metadata` — run without `TF_ACC`) and acceptance tests (`TestAcc...`) that use
`resource.ParallelTest` with `testAccProtoV6ProviderFactories`
(`providerserver.NewProtocol6WithError(New("test")())`) and the `testAccPreCheck` helper, which
requires `TF_ACC`, `RUSTFS_ENDPOINT`, `RUSTFS_USER` and `RUSTFS_SECRET`.

**Resource lifecycle paths** (`provider/lifecycle_test_harness_test.go`): every resource carries a
`Test<Name>ResourceLifecyclePaths` that drives `Create`/`Read`/`Update`/`Delete`/`Configure`
against a canned `httptest` server (`cannedClient` for one answer to everything, `routedClient` for
one route per method and path) and asserts the diagnostic summary *and* detail, `RemoveResource`
for a missing object, and that a failed create wrote no partial state. A new resource is not done
until it has that table. Missing-object detection stays narrow: the structured admin/S3 error code,
or — only where the endpoint has no code — its own wording, never a blanket `not found` substring.

**Live CRUD tests:** `admin_client_test.go`, `lifecycle_test.go`, `policy_test.go`,
`quota_test.go`, `service_account_test.go` and `user_account_test.go` read `RUSTFS_ENDPOINT`,
`RUSTFS_USER` and `RUSTFS_SECRET` and dial the real endpoint. They skip themselves when those are
unset, so `go test ./...` is green without a server; run the Docker/Podman environment to exercise
them live before claiming a CRUD change works.
