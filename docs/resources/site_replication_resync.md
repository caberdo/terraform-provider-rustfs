# rustfs_site_replication_resync Resource

Start, cancel or inspect a RustFS site-replication resync (PUT /rustfs/admin/v3/site-replication/resync/op).

**A resync re-copies data between sites.** It walks the replicated buckets and depends on the server's existing site-replication configuration, so it can move a large amount of data. Every operation names the target peer by `deployment_id`; `operation = "status"` only reads that peer's current operation.

Every configurable attribute carries RequiresReplace: changing `operation`, `peer`, a peer field or `triggers` replaces the resource and runs a new operation instead of editing the recorded one, so `Update` never edits in place.

Destroying this resource does nothing on the server. The provider does not cancel a resync on destroy: cancelling must be an explicit `operation = "cancel"` apply, because a resync is operator-driven and a `terraform destroy` should not silently change replication state. Read only echoes the recorded result, since the server has no neutral read by id.

Read `rustfs_site_replication_status` first to get each peer's `deployment_id`.

## Example Usage

```terraform
# Read the group first: rustfs_site_replication_status is the surface that
# reports each peer's deployment_id, which a resync needs to identify its
# target. The data source is read-only, so reading it is always safe.
data "rustfs_site_replication_status" "group" {
}

# Inspect the peer's resync without starting one. `status` never moves data;
# `start` re-copies the replicated buckets to the peer and `cancel` stops an
# active resync, both of which change replication state and should be applied
# deliberately.
resource "rustfs_site_replication_resync" "status" {
  operation = "status"

  peer = {
    name = one([
      for site in data.rustfs_site_replication_status.group.sites : site.name
      if site.name == "site-b"
    ])
    deployment_id = one([
      for site in data.rustfs_site_replication_status.group.sites : site.deployment_id
      if site.name == "site-b"
    ])
  }
}

output "site_replication_resync" {
  value = {
    op_type = rustfs_site_replication_resync.status.op_type
    status  = rustfs_site_replication_resync.status.status
    state   = rustfs_site_replication_resync.status.state
    message = rustfs_site_replication_resync.status.message
  }
}
```

## Schema

### Required

- `operation` (String) Operation to run: `start` re-copies data to the peer, `cancel` stops the peer's current resync, `status` reads it without changing anything. Changing it replaces the resource and runs the new operation.
- `peer` (Attributes) Target peer. Every operation requires `deployment_id`, which the server uses to identify the peer. Changing the block replaces the resource and runs the operation against the new peer. (see [below for nested schema](#nestedatt--peer))

### Optional

- `triggers` (Map of String) Arbitrary values that are not sent to the server. Change one to run the operation again; without a change Terraform does not repeat it.

### Read-Only

- `id` (String) Resource identifier: the resync id the server returned, or `<operation>/<deployment_id>` when the server returned none.
- `message` (String) Error detail the server returned, empty when the operation did not fail. A `status = "failed"` result is not a provider error: the apply records what the server answered.
- `op_type` (String) Operation type the server echoed.
- `resync_id` (String) Resync operation id the server returned; empty when the server returned none.
- `state` (String) State the server returned for the operation, when it reports one.
- `status` (String) Status the server returned for the operation.
