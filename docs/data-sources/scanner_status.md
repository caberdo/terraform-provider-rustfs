# rustfs_scanner_status Data Source

Runtime status of the RustFS object scanner (GET /rustfs/admin/v3/scanner/status): cycle state, the last completed cycle and its counters, usage publication and heal observation, and data-movement pause state. The scanner's tuning knobs stay in the `scanner` subsystem of `rustfs_config` or in the server environment; this data source only observes them. RustFS 1.0.5 adds the usage-publication and heal-observation blocks; on 1.0.1 through 1.0.4 their attributes are null and the read still succeeds. Heal observation is read-only: this data source never starts, pauses or cancels a heal.

## Example Usage

```terraform
# Observe the scanner; tuning stays in the scanner subsystem of rustfs_config
# or in the server environment (RUSTFS_SCANNER_* variables).
data "rustfs_scanner_status" "current" {}

output "scanner_freshness" {
  value = data.rustfs_scanner_status.current.freshness_state
}

output "scanner_last_cycle" {
  value = {
    result      = data.rustfs_scanner_status.current.last_cycle_result
    duration    = data.rustfs_scanner_status.current.last_cycle_duration_seconds
    objects     = data.rustfs_scanner_status.current.last_cycle_objects_scanned
    directories = data.rustfs_scanner_status.current.last_cycle_directories_scanned
  }
}

output "scanner_usage_rebuild_pending" {
  value = data.rustfs_scanner_status.current.usage_bootstrap_rebuild_pending
}

# RustFS 1.0.5 reports the most recent usage-publication attempt separately from
# usage_publication_state. On 1.0.1 through 1.0.4 these attributes are null.
output "scanner_usage_publication" {
  value = {
    class            = data.rustfs_scanner_status.current.usage_publication_class
    outcome          = data.rustfs_scanner_status.current.usage_publication_outcome
    pending_buckets  = data.rustfs_scanner_status.current.usage_publication_pending_bucket_count
    snapshot_updated = data.rustfs_scanner_status.current.usage_publication_snapshot_updated_at_unix_secs
  }
}

# Heal observation is read-only: it never starts, pauses or cancels a heal.
# The candidate arrays stay available as compact JSON for entries whose values
# the provider does not name.
output "scanner_heal_observation" {
  value = {
    retained_pending = data.rustfs_scanner_status.current.heal_retained_pending_tasks
    terminal         = data.rustfs_scanner_status.current.heal_terminal_candidate_count
    unknown          = data.rustfs_scanner_status.current.heal_unknown_candidate_count
    integrity_state  = data.rustfs_scanner_status.current.heal_integrity_state
    candidates       = data.rustfs_scanner_status.current.heal_candidates_json
  }
}
```

## Schema

### Read-Only

- `current_cycle` (Number) Number of the running or most recent scanner cycle.
- `current_cycle_active` (Boolean) Whether a scanner cycle is running.
- `current_scan_mode` (String) Scan mode of the running or most recent cycle, `normal` or `deep`.
- `cycle_recovery_reason` (String) Reason recorded with the cycle-recovery state, when one is present.
- `cycle_recovery_state` (String) Scanner cycle-recovery state on this node, for example `healthy` or `recovery-required`.
- `cycles_completed` (Number) Number of cycle completions retained in the status window.
- `data_movement_paused` (Boolean) Whether a pool decommission or rebalance currently pauses scanner metadata publication.
- `disabled_reason` (String) Why the scanner is disabled, when it is.
- `effective_cycle_interval_seconds` (Number) Effective interval between scanner cycles, including clean-idle backoff.
- `enabled` (Boolean) Whether the scanner is enabled on this server.
- `failed_cycles` (Number) Number of failed scanner cycles since startup.
- `freshness_state` (String) Scanner freshness: `fresh`, `stale` or `unknown`.
- `heal_candidates_json` (String) Compact JSON object holding the server's `terminal_candidates` and `unknown_candidates` arrays. The entries keep their execution, disposition, scope, scan mode and reason grouping, so a value this provider does not name needs no schema change. Null on RustFS 1.0.1 through 1.0.4; `status_json` carries the whole response.
- `heal_integrity_state` (String) Integrity verdict of the heal observation window, for example `unknown`. It stays `unknown` while any candidate lacks terminal proof, including when `heal_retained_pending_tasks` is zero. Null on RustFS 1.0.1 through 1.0.4.
- `heal_retained_pending_tasks` (Number) Heal tasks this node still retains as pending, from `heal_observation`. Null when the local observer is not running or the server does not report the block (RustFS 1.0.1 through 1.0.4).
- `heal_terminal_candidate_count` (Number) Sum of the retained terminal heal observation groups, from `heal_observation.terminal_candidates[].count`. It covers the local observation window, not a lifetime total. Null on RustFS 1.0.1 through 1.0.4.
- `heal_unknown_candidate_count` (Number) Sum of the retained unknown heal observation groups, from `heal_observation.unknown_candidates[].count`: admission rejections, overflow, loss, expiry and missing terminal proof. Null on RustFS 1.0.1 through 1.0.4.
- `id` (String) Data source identifier.
- `last_cycle_directories_scanned` (Number) Directories the last cycle scanned.
- `last_cycle_duration_seconds` (Number) Wall-clock duration of the last cycle in seconds.
- `last_cycle_end_unix_secs` (Number) Unix time at which the last cycle ended, or `0` before the first completed cycle.
- `last_cycle_objects_scanned` (Number) Object versions the last cycle scanned.
- `last_cycle_result` (String) Result of the last cycle, for example `success`, `partial`, `superseded` or `error`.
- `maintenance_primary_control` (String) Primary reason scanner maintenance work is blocked, deferred or paced, or `none`.
- `pause_backlog_phase` (String) Catch-up phase of the pause ledger: `idle`, `paused`, `catching_up` or `retry_exhausted`.
- `status_json` (String) Raw JSON response as returned by the RustFS admin API. It always carries the full body, including any block or field this data source does not model, so it is the escape hatch when a newer server adds scanner telemetry.
- `superseded_cycles` (Number) Number of cycles superseded by newer writes since startup.
- `usage_bootstrap_rebuild_pending` (Boolean) Whether a usage-state full rebuild is still pending after a reset.
- `usage_dirty_pending_buckets` (Number) Buckets whose usage is marked dirty and waiting for a scanner pass.
- `usage_last_durable_success_unix_secs` (Number) Unix time of the last durable usage publication, or `0` when none is recorded.
- `usage_publication_class` (String) Class of the most recent publication attempt, for example `complete_converged`, `complete_pending`, `progress_only`, `observational` or `unknown`. The server defines these values, so this stays a string rather than a fixed enum. Null on RustFS 1.0.1 through 1.0.4.
- `usage_publication_cycle` (Number) Scanner cycle of the most recent usage publication attempt. It is the cycle the attempt observed and can differ from `current_cycle`. Null on RustFS 1.0.1 through 1.0.4.
- `usage_publication_observed_at_unix_secs` (Number) Unix time at which this node recorded the publication observation. Null when the server did not report it, including on RustFS 1.0.1 through 1.0.4.
- `usage_publication_outcome` (String) Persistence outcome of the most recent publication attempt, for example `saved`. Server-defined, so this stays a string. Null on RustFS 1.0.1 through 1.0.4.
- `usage_publication_pending_bucket_count` (Number) Buckets still pending in the authoritative usage snapshot the attempt published. Null when the server could not confirm the snapshot (progress-only, observational, failed or unverified); zero only for a confirmed converged snapshot. The live `usage_dirty_pending_buckets` count can change independently after publication.
- `usage_publication_scanner_epoch` (Number) Scanner epoch of the most recent usage publication attempt. Null on RustFS 1.0.1 through 1.0.4, which do not report the block.
- `usage_publication_snapshot_updated_at_unix_secs` (Number) Unix time at which the published usage snapshot was last updated. Null when the server did not report it, including on RustFS 1.0.1 through 1.0.4.
- `usage_publication_state` (String) State of the last scanner usage publication (`metrics.usage_freshness.last_publication_state`). This is the older field: it reports the retained publication state, while the `usage_publication_*` attributes describe the most recent publication attempt, including whether it converged (`usage_publication_class`) and how many buckets it left pending.
