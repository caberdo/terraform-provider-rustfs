# rustfs_bucket_usage Data Source

Read the scanner's usage accounting for one bucket or prefix (GET /rustfs/admin/v3/usage/{bucket}). The numbers are not real-time: the scanner publishes them after a cycle, the endpoint caches a computed answer for up to 30 seconds, and `sets_reporting` below `sets_total` means at least one erasure set could not contribute, so the counters are a lower bound. A newly created bucket can report zeros until the first cycle covers it. An unknown bucket fails the read instead of reporting zeros. The read also performs an S3 `HeadBucket` existence check, so the provider credentials need `s3:ListBucket` (or equivalent) on the bucket in addition to the admin permission that serves the usage route. This is the scanner's eventually-consistent accounting, not the quota subsystem's view: use `rustfs_quota_stats` for the configured quota limit, the quota subsystem's usage and the remaining headroom.

## Example Usage

```terraform
# Usage accounting is produced by the scanner, not in real time: the numbers
# lag the last cycle, the endpoint caches for up to 30 seconds, and
# sets_reporting below sets_total means at least one erasure set is missing
# from the answer.
data "rustfs_bucket_usage" "logs" {
  bucket = "logs"
  prefix = "2026/"
}

output "logs_usage" {
  value = {
    size         = data.rustfs_bucket_usage.logs.size
    objects      = data.rustfs_bucket_usage.logs.objects
    versions     = data.rustfs_bucket_usage.logs.versions
    last_update  = data.rustfs_bucket_usage.logs.last_update
    set_coverage = "${data.rustfs_bucket_usage.logs.sets_reporting}/${data.rustfs_bucket_usage.logs.sets_total}"
    sub_prefixes = data.rustfs_bucket_usage.logs.sub_prefixes
  }
}
```

## Schema

### Required

- `bucket` (String) Name of the bucket.

### Optional

- `max_entries` (Number) Maximum sub-prefix rows to return. The server defaults to 1000 and accepts 1..10000; the largest rows remain when the breakdown is truncated.
- `prefix` (String) Limit the answer to this prefix. An empty value (the default) reports the whole bucket. The server trims leading and trailing slashes.

### Read-Only

- `compacted` (Boolean) Every reporting set had this prefix compacted: the aggregate is valid but the sub-prefix breakdown is empty on disk.
- `delete_markers` (Number) Delete-marker count accounted for the bucket or prefix.
- `id` (String) Data source identifier, the bucket and prefix that were read.
- `json` (String) Raw server response, for fields this data source does not surface yet.
- `last_update` (String) Newest scanner update across the reporting sets, in RFC 3339. Null when no set has published usage for this bucket yet.
- `objects` (Number) Current object count accounted for the bucket or prefix.
- `sets_reporting` (Number) Erasure sets whose usage cache held this bucket and prefix.
- `sets_total` (Number) Erasure sets the deployment has.
- `size` (Number) Bytes accounted for the bucket or prefix.
- `sub_prefixes` (Attributes List) One level of sub-prefix breakdown, largest first. (see [below for nested schema](#nestedatt--sub_prefixes))
- `sub_prefixes_partial` (Boolean) At least one reporting set could not attribute its objects to a sub-prefix, so the breakdown is incomplete while the aggregate stays valid.
- `truncated` (Boolean) The breakdown exceeded `max_entries`; only the largest rows are returned.
- `versions` (Number) Version count accounted for the bucket or prefix.
