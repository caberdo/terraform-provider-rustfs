# rustfs_site_replication_status Data Source

Read the site-replication state of the RustFS deployment: the peers from GET /rustfs/admin/v3/site-replication/info, the per-site replication counters from GET /rustfs/admin/v3/site-replication/status, and the topology counts from GET /rustfs/admin/v3/site-replication/metainfo. Read-only: it never changes the group.

`status_available` reports whether the status route answered. RustFS 1.0.1 through 1.0.3 implement it; a server that answers it as unimplemented still yields the info and metainfo result with `status_available = false`, empty status collections and every site's `sync_state` set to `unknown`, instead of failing the read. Any other status error fails the read, and so does a metainfo error: the metainfo surface is what this data source is for.

## Example Usage

```terraform
# Read the site-replication group and its peers. No inputs: the data source
# always reports the deployment the provider is configured against.
data "rustfs_site_replication_status" "group" {
}

output "site_replication_enabled" {
  value = data.rustfs_site_replication_status.group.enabled
}

# Peer deployment IDs are what a resync targets, and only this data source
# reports them.
output "site_replication_peers" {
  value = {
    for site in data.rustfs_site_replication_status.group.sites : site.name => {
      endpoint      = site.endpoint
      deployment_id = site.deployment_id
      sync_state    = site.sync_state
    }
  }
}
```

## Schema

### Read-Only

- `api_version` (String) Site-replication API version the server reports.
- `deployment_id` (String) Deployment ID of this site, as reported by the metainfo route; the info route does not carry it.
- `enabled` (Boolean) Whether site replication is enabled on this deployment. Read from `site-replication/info`, falling back to `site-replication/status` when info reports it disabled but the live status reports it enabled.
- `id` (String) Data source identifier.
- `max_buckets` (Number) Highest bucket count any site reports, or 0 when the status route is unavailable.
- `max_groups` (Number) Highest IAM group count any site reports, or 0 when the status route is unavailable.
- `max_ilm_expiry_rules` (Number) Highest lifecycle-expiry rule count any site reports, or 0 when the status route is unavailable.
- `max_policies` (Number) Highest IAM policy count any site reports, or 0 when the status route is unavailable.
- `max_users` (Number) Highest IAM user count any site reports, or 0 when the status route is unavailable.
- `metainfo` (Attributes) Topology summary of this site. The route returns every replicated document; only its size and identity are exposed here. (see [below for nested schema](#nestedatt--metainfo))
- `name` (String) Name of this (local) site.
- `peer_errors` (Attributes List) Peers the status read could not reach, sorted by name. (see [below for nested schema](#nestedatt--peer_errors))
- `retry_failed` (Number) Peer deliveries that exhausted their retries, or 0 when the status route is unavailable.
- `retry_last_error` (String) Most recent delivery error the retry queue recorded, empty when there is none or the status route is unavailable.
- `retry_pending` (Number) Peer deliveries still queued for retry, or 0 when the status route is unavailable.
- `sites` (Attributes List) Every site in the group, sorted by name. (see [below for nested schema](#nestedatt--sites))
- `status_available` (Boolean) Whether the status route answered. When false, `sites`, `peer_errors` and the status counters are empty and every `sync_state` is `unknown`.
