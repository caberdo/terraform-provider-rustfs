# rustfs_temporary_accounts Data Source

List the temporary (STS) access keys RustFS reports, optionally including service accounts.

`rustfs_service_accounts` lists the IAM service accounts instead: those are the persisted, long-lived API keys a parent user owns, while this data source lists STS temporary keys (set `include_service_accounts` to add the service accounts to this listing).

RustFS has no route that lists every temporary account: `temporary-account-info` takes one access key, so the listing comes from `list-access-keys-bulk`. The provider reads that route once per identity provider to attribute each key: the `idp/ldap` and `idp/openid` routes only report keys whose claims match, so a key the generic route reports and neither scoped route does is `builtin`.

The server enumerates IAM users, so an external identity that RustFS does not persist as an IAM user is only listed when `parent_user` names it.

No secret key or session token is ever returned for a listed access key. Set `include_policies` to read each key's effective policy as well; that costs one lookup per key.

## Example Usage

```terraform
# List every temporary (STS) access key the server reports, with the identity
# provider RustFS attributes each key to.
data "rustfs_temporary_accounts" "all" {}

output "temporary_access_keys" {
  value = [
    for account in data.rustfs_temporary_accounts.all.accounts : {
      access_key    = account.access_key
      parent_user   = account.parent_user
      user_provider = account.user_provider
      expiration    = account.expiration
    }
  ]
}

# Restrict one provider and parent user, and read each key's effective policy.
# include_policies costs one admin lookup per key.
data "rustfs_temporary_accounts" "openid_sessions" {
  user_provider    = "openid"
  parent_user      = "alice@example.com"
  include_policies = true
}

# Long-lived service accounts share the bulk listing; opt in to see them too.
data "rustfs_temporary_accounts" "with_service_accounts" {
  include_service_accounts = true
}
```

## Schema

### Optional

- `include_policies` (Boolean) Read the effective policy, implied-policy flag and account status of every listed key. Omitted means false. This costs one admin lookup per key and fails the read if a key is revoked while it runs.
- `include_service_accounts` (Boolean) Also list long-lived service accounts stored beside the temporary keys. Omitted means false.
- `parent_user` (String) Only list keys owned by this parent user. Naming the user also reaches an external identity that the server does not enumerate as an IAM user.
- `user_provider` (String) Only list keys for this identity provider: `builtin`, `ldap` or `openid` (`openid` covers OIDC). Omit to list every provider.

### Read-Only

- `accounts` (Attributes List) Temporary access keys sorted by parent user, then access key. (see [below for nested schema](#nestedatt--accounts))

### Nested Schema for `accounts`

Read-Only:

- `access_key` (String) Access key identifier. It is a public identifier, not a secret.
- `account_status` (String) Account status the server reports, for example `on` or `off`. It is read from the bulk listing unless `include_policies` is set, in which case the per-key lookup supplies it. Null when the server reports none.
- `description` (String) Optional description of the key.
- `expiration` (String) Expiry of the credential in RFC 3339, or null when the server reports none.
- `implied_policy` (Boolean) Whether the key's effective policy is the parent user's implied policy rather than an explicit session policy. Null unless `include_policies` is set: the bulk listing does not report it.
- `kind` (String) `sts` for a temporary credential or `service-account` when `include_service_accounts` is set.
- `name` (String) Optional display name of the key.
- `parent_user` (String) User the temporary credential was issued for.
- `policy` (String) Effective policy document (JSON) when `include_policies` is set, otherwise null.
- `user_provider` (String) Identity provider the server attributes the key to: `builtin`, `ldap` or `openid`.
