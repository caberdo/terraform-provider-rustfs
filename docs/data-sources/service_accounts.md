# rustfs_service_accounts Data Source

List the IAM service accounts (`GET /rustfs/admin/v3/list-service-accounts`), the long-lived API keys a parent user owns. This is a different surface from `rustfs_temporary_accounts`: that data source lists STS temporary keys (the short-lived credentials minted by AssumeRole), while this one lists the persisted IAM service accounts.

The listing never returns a secret key, and the provider blanks the field on every account it receives, so no key material can reach Terraform state. Manage accounts with `rustfs_serviceaccount`.

The route is served by RustFS 1.0.1 and later; a server that does not implement it fails the read with a capability diagnostic naming the route.

## Example Usage

```terraform
# List the IAM service accounts the server persists. This is not the STS
# temporary-key surface: data.rustfs_temporary_accounts lists those.
data "rustfs_service_accounts" "all" {}

output "service_account_keys" {
  value = [
    for account in data.rustfs_service_accounts.all.accounts : {
      access_key  = account.access_key
      parent_user = account.parent_user
      status      = account.account_status
    }
  ]
}
```

## Schema

### Optional

- `user` (String) IAM user whose service accounts are listed. Omit it to list the calling identity's accounts; naming another user is a cross-user listing and needs the ListServiceAccounts admin action.

### Read-Only

- `accounts` (Attributes List) Service accounts sorted by access key. (see [below for nested schema](#nestedatt--accounts))
- `id` (String) Data source identifier.

### Nested Schema for `accounts`

Read-Only:

- `access_key` (String) Access key identifier, which is the identifier `rustfs_serviceaccount` manages. It is a public identifier, not a secret.
- `account_status` (String) Account status the server reports, for example `on` or `off`.
- `description` (String) Description of the account. Null when the server reports none.
- `expiration` (String) Expiry of the account in RFC 3339, or null when the server reports none.
- `implied_policy` (Boolean) Whether the account inherits the parent user's policy (`true`) or carries its own in `policy` (`false`).
- `name` (String) Display name of the account.
- `parent_user` (String) User the service account belongs to.
- `policy` (String) Effective policy document (JSON). Null when the account implies the parent policy.
